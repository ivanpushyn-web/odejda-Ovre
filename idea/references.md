## Откуда пришла идея (мой взгляд, дословно)

> Я сейчас вижу четко конкурентов, ребята, особенно на американском рынке,
> которые сделали следующее. У них полностью автоматизирован процесс озвучки,
> полностью автоматизирован монтаж. Они используют либо аватаров, либо без
> аватаров просто озвучку и генерацию моушн графики. И это очень круто
> работает. Я прям вижу такие риелсы, они прям залетают, набирают миллионы.
> При этом я вижу полную автоматизацию даже в системе истории, биологии и
> науки. И причем самое тупое, что я сам смотрю этот контент, понимаю, что это
> сделал я, и мне очень нравится такой контент. То есть я сам его смотрю. И мне
> хочется понять, наверняка кто-то решал мою проблему, кто-то полностью написал
> пайплайн производства такого контента, где не участвовал человек, скорее
> всего, на американском рынке. Особенно это очень развито в теме заработка на
> Ютубе, все дела у нас.

## Что искали и как читать пометки

Проблема, которую искали: конвейер без человека по всей цепочке из superidea -
разведка конкурента (скачать, транскрибировать, досье, трекинг, «почему зашло»,
воронка) → идеи → сценарий → озвучка / аватар / визуал → монтаж → постинг на
много аккаунтов → цифры и корректировка. Акцент, как в моём взгляде выше, на
производственной части.

Где смотрели: GitHub и n8n-шаблоны, BlackHatWorld, Hacker News, dev.to, Skool,
Substack, документация Meta / TikTok / YouTube, арабоязычные YouTube-разборы,
фриланс-биржи مستقل / خمسات / نفذلي, арабские TTS-сервисы. Reddit для
инструментов разведки оказался закрыт целиком, X/Twitter тоже - это дыра,
отмечаю честно. Русскоязычные источники не смотрели, задачи не было.

Пометки: **беру** - ложится на Ovre как есть; **беру с оговоркой** - беру
принцип, реализацию меняю; **не подходит** - чужая специфика, с причиной.

Контекст для пометок: Ovre - премиум женская одежда, весь трафик в Instagram,
в кадре аватар или сгенерированная модель, язык русский, мера успеха - продажи.
Контроль передаю поэтапно по бенчмарку 90% принятого без правок. Умная модель
только на паттерны, выбор, адаптацию и сценарий; всё остальное дёшево.

## 1. Готовые конвейеры производства (открытый код)

### MoneyPrinterTurbo
Источник: https://github.com/harry0703/MoneyPrinterTurbo (~122k звёзд, активен 2026)
Суть: самый крупный референс «тема → сценарий (LLM) → TTS → сток Pexels/Pixabay
или AI-видео → FFmpeg с субтитрами». Любой шаг подменяется провайдером:
LLM (OpenAI/Claude/Gemini/DeepSeek/Ollama), TTS (edge-tts бесплатно, Azure,
ElevenLabs, Kokoro, Fish), субтитры двух режимов - дешёвый по таймингам TTS и
точный через faster-whisper. Batch-файл до 100 задач с override параметров,
REST API, есть «skill-документ», чтобы агент сам ставил и запускал.
Пометка: **беру с оговоркой.** Беру архитектуру «абстракция провайдеров + batch
+ два режима субтитров». Не беру сам продукт: стоковая картинка по ключевым
словам - это то, что YouTube и Instagram с 2025 года считают массовым
неоригинальным контентом, для премиум-бренда неприемлемо.

### OpenMontage
Источник: https://github.com/calesthio/OpenMontage (56k звёзд, 2026, AGPL)
Суть: «агентная студия» внутри Claude Code / Cursor: 12 пайплайнов (аватар-
спикер, анимированный объяснитель, документальный монтаж, дубляж), 700+
markdown-скиллов, по одному «режиссёрскому» скиллу на стадию. Обязательная
research-стадия перед сценарием с цитированием источников. Скоринг провайдеров
по 7 измерениям. Slideshow risk score из 6 признаков (повторяемость,
декоративность визуала, слабость движения, перегруз типографикой) - при
критическом значении рендер блокируется. Пост-рендер самопроверка: ffprobe,
выборка кадров на чёрные, тишина/клиппинг, наличие субтитров. JSON-чекпоинты,
бюджетные режимы, пауза при действии дороже $0.50.
Пометка: **беру.** Это самое близкое к моей идее «скиллы + агент» и готовая
механика QC без человека. Особенно slideshow risk score и бюджетные гейты.
Оговорка: у них человеческие approval-gates обязательны на всех стадиях - у
меня они снимаются по бенчмарку 90%, это надо будет вырезать. AGPL - для
продажи как MCP позже это ограничение.

### Pixelle-Video (Alibaba AIDC)
Источник: https://github.com/ATH-MaaS/Pixelle-Video (28k звёзд, июнь 2026)
Суть: сцена = HTML-шаблон (статичный / картинка / видео × портрет / ландшафт /
квадрат), медиа-провайдер и шаблон разделены. Генерация через ComfyUI или
прямые API (Kling, Seedance, WAN), TTS с клонированием голоса по референсу.
Пометка: **беру** принцип «сцена как HTML-шаблон»: брендовые лейауты Ovre
(тёмная тема, лого, типографика) делаются один раз и переиспользуются. Сам
проект не беру: документация и провайдеры китайские, постинга нет.

### HyperFrames (HeyGen)
Источник: https://github.com/heygen-com/hyperframes (48k звёзд, 2026)
Суть: «напиши HTML - получи MP4»: data-атрибуты таймингов, GSAP/CSS/Lottie,
детерминированный рендер в headless Chrome + FFmpeg. Сделано под агентов:
агенту проще писать HTML, чем JSX Remotion.
Пометка: **беру** как рендер-движок моушн-графики для агента. Это ровно
«генерация моушн-графики без человека» из моего взгляда, и она в бренд-стиле.

### ai-shortVideo-pipeline (myccarl)
Источник: https://github.com/myccarl/ai-shortVideo-pipeline (2026)
Суть: семь слоёв (тема → креатив → визуал → аудио → пост-продакшн →
дистрибуция → оптимизация). Три приёма без человека: prompt anchoring
(описание героя фиксируется во всех промптах сегментов), CLIP-гейт (кейфрейм,
не совпавший с промптом, отбраковывается до дорогой генерации видео),
AV-sync auto-rescue в 4 ступени (темп аудио → паддинг видео → переписать
нарратив → перегенерировать сегмент).
Пометка: **беру** все три приёма. Prompt anchoring - прямой ответ на
«одна и та же модель во всех роликах». Китайские провайдеры не беру.

### youtube-shorts-pipeline (rushindrasinha)
Источник: https://github.com/rushindrasinha/youtube-shorts-pipeline (2.3k, 2026)
Суть: «niche profile» как единый конфиг всех стадий (тон, темп, паттерны хуков,
CTA, стиль субтитров, музыка, обложка), 15 профилей. Веб-исследование до
сценария как «anti-hallucination gate». Субтитры в двух форматах: ASS с
подсветкой слова для вшивания + SRT для платформы. Экономика посчитана:
$0.11 / $0.04 / $0 за ролик.
Пометка: **беру** идею профиля: у Ovre это `brand-guidelines.md` + `values.md`
+ `avatar.md`, переведённые в машинный конфиг, который читают все стадии.

### AutoShorts AI (SaarD00)
Источник: https://github.com/SaarD00/AI-Youtube-Shorts-Generator (2026)
Суть: LLM отдаёт JSON из 8–9 сцен по схеме Hook → Context → Mechanism → Twist,
у каждой сцены два визуальных ключа. A/B split: первая половина сцены - клип A,
вторая - клип B, смена картинки посреди фразы. В одну из средних сцен
случайно вставляется брендовый маскот.
Пометка: **беру** «сценарий = JSON сцен» и «брендовый якорь в середине». Для
Ovre якорь - деталь ткани крупно или лого. Сток и отсутствие субтитров не беру.

### yt-faceless-automation (collij22)
Источник: https://github.com/collij22/yt-faceless-automation (2025–2026)
Суть: 8 субагентов Claude Code + 5 n8n-workflow. Перцептивная дедупликация
ассетов (pHash + URL), чтобы один и тот же кадр не повторялся между роликами.
Кэш TTS. Fallback-карточки, если API ассетов упало. Валидация монотонности
таймлайна через ffprobe.
Пометка: **беру** pHash-дедуп и кэш TTS. Длинные YouTube-видео и Openverse-
картинки не подходят: у меня Reels и своя одежда.

### multiagent-youtube (rafaelgreca)
Источник: https://github.com/rafaelgreca/multiagent-youtube (февраль 2026)
Суть: единственный найденный явный «LLM-судья сценария с порогом и петлёй»:
Critic оценивает сценарий (с фактчеком), при score < 0.8 - переписывание.
Пометка: **беру.** Это механика этапа «сценарий очень тщательно обдумывается,
выпиливаются громкие обещания, хуманизируется» - до того, как он идёт ко мне
на валидацию. Порог берём как настраиваемый.

### youtube-autopilot (khaoss85)
Источник: https://github.com/khaoss85/youtube-autopilot (2026)
Суть: QualityReviewer с 8-пунктовой проверкой (бренд-тон, запрещённые темы,
копирайт, медицинские заявления). Память недавних заголовков против
самоповтора. Изолированные workspace для нескольких каналов с разным голосом.
`publish` - единственный путь загрузки, «никогда не автоматизируется».
Пометка: **беру** список запрещённого как конфиг (для одежды: «хит сезона»,
«успей купить», обещания посадки без оговорки) и память тем. Ручной publish не
беру - у меня он уходит на автомат по бенчмарку.

### MoneyPrinterPlus (китайская ветка)
Источник: https://github.com/ddean2009/MoneyPrinterPlus (7k, GPL-3)
Суть: режим «混剪» - батч-микс до 100 роликов за прогон из библиотеки
сегментов; автопубликация через Selenium в платформы без API.
Пометка: **не подходит.** Selenium-постинг = неофициальная автоматизация,
для Instagram это риск бана; батч-микс даёт одинаковые ролики, что Instagram с
апреля 2026 наказывает. GPL-3 запрещает коммерческое использование.

### Vanta
Источник: https://github.com/itsjwill/vanta (2026)
Суть: SDK на Remotion, собравший 40+ OSS-репо (клон голоса GPT-SoVITS / F5,
аватары MuseTalk / LatentSync / InfiniteTalk, WhisperX-субтитры, Wan / LTX
видео) и проверивший все лицензии на коммерческую пригодность.
Пометка: **беру** как справочник «что можно коммерчески». Сам SDK - под
вопросом, batch из CSV у них только в roadmap.

### Строительные блоки, которые повторяются везде
- remotion-dev/template-tiktok - whisper.cpp + `createTikTokStyleCaptions`
  с подсветкой активного слова. **Беру** формат субтитров.
- Kokoro-FastAPI - OpenAI-совместимая TTS с таймстампами для субтитров без
  Whisper. **Беру с оговоркой**: русский голос надо слушать.
- Captacity - `pip install`, субтитры одним модулем. **Беру** как запасной.
- OpenShorts / claude-shorts - рубрика оценки сегмента (hook 30% / coherence
  25% / emotion 20% / value density 15% / payoff 10%) и резка по границам слов
  и тишины. **Беру** рубрику как шаблон для LLM-судьи.
- Dark2C/Viral-Faceless-Shorts-Generator - forced alignment через aeneas
  вместо Whisper при TTS-озвучке. **Беру** как дешёвую альтернативу.
- Аватары из OSS: MuseTalk (скорость), LatentSync (качество), InfiniteTalk
  (длина). Вывод раздела: в полностью автоматических пайплайнах самодельный
  lip-sync почти не используют, берут HeyGen по API. **Беру** HeyGen по API
  как дефолт, OSS - как эксперимент под бюджет.

## 2. Приёмы сценария и хука (из практики)

### Первое слово в пределах 0,5 секунды, пять типов хука
Источник: https://virvid.ai/blog/first-3-seconds-hook-faceless-shorts-2026
Суть: bold claim / curiosity gap / микро-история с середины сцены / визуальный
шок / прямой вопрос. Никаких интро, лого, приветствий. Субтитры с первого
слова, больше 60% смотрят без звука. Ориентир Viewed-vs-Swiped-Away 70–90%,
ниже 60% - хук считается сломанным.
Пометка: **беру** как правила для LLM-судьи и как метрику. «Визуальный шок»
для премиум-тона заменяю на «движение ткани / reveal образа».

### Визуальное изменение каждые 2–3 секунды, 70%+ удержания
Источник: https://virvid.ai/blog/ai-shorts-increase-retention-watch-time
Суть: зум, джамп-кат, субтитр, SFX каждые 2–3 с; вирусные шортсы держат в
среднем 76% удержания, >75% дают ~3× дистрибуцию; 15-секундные легче добивают
100%; смена музыки в середине «перезапускает» внимание.
Пометка: **беру** как параметры автомонтажа (скилл autocut) и как проверку в QC.

### Сценарий с жёстким лимитом символов и фиксированной схемой
Источник: https://n8n.io/workflows/8290-automate-faceless-shorts-with-openai-runwayml-and-elevenlabs-script-to-social-media/, https://dev.to/grewup/n8n-workflow-that-auto-creates-viral-youtube-shorts-while-you-sleep-2moe
Суть: промпт требует 213–223 символа на 20 секунд; схема Hook → Problem →
Solution → Proof → CTA; Whisper-таймкоды как «клей» между голосом и сценами.
Пометка: **беру** лимит символов и таймкоды как клей. Схему беру с оговоркой:
для одежды «Problem → Solution» звучит как реклама, скорее «повод → образ →
деталь → куда прийти».

### 4–6 хуков на одном теле ролика, спринт в 4 недели
Источник: https://sink-or-swim-marketing.com/blog/tiktok-creative-center-best-practices-hook-retention-2025/
Суть: неделя 1 - собрать хуки, сделать 4–6 вариантов открытия на одном теле;
неделя 2 - выпустить одновременно; неделя 3 - сравнивать 3-секундное удержание
и completion, не CTR; неделя 4 - масштабировать победителя, две новых вариации.
Пометка: **беру.** Это готовый цикл «ежедневная рефлексия по цифрам» и дешёвый
способ разводить контент по нескольким аккаунтам: один ролик, разные хуки.

### 100+ кандидатов → 2 недели теста → тираж шаблона
Источник: https://link.springer.com/article/10.1007/s00146-026-03254-9 (этнография китайских «матриц», 2026)
Суть: на старте генерируют 100+ вариантов, тестируют на аккаунтах две недели,
победивший формат тиражируют. Критерий отбора: «шаблонизируемо ли это».
Пометка: **беру** принцип тест-выборки. Не беру объёмы (30–50 роликов в день на
человека) и жанры - для премиум-бренда это самоубийство охватов.

### Маленькие правки внутри рабочего формата вместо нового жанра
Источник: https://www.fortune.com/2025/12/30/ai-slop-faceless-youtube-accounts-adavia-davis-user-generated-content
Суть: крупнейший задокументированный оператор (5 каналов, ~2M просмотров/день)
не изобретает форматы, а ищет «маленькие преимущества внутри того, что уже
работает». При этом у него 2 часа контроля в день плюс люди по нишам:
«полностью без человека» не существует даже там.
Пометка: **беру** принцип. Это подтверждает мою ставку «красть стратегию у
тех, кто уже нащупал». Формат «6 часов истории для сна» не подходит.

### Микро-ниша, а не тема
Источник: https://news.ycombinator.com/item?id=45949988
Суть: не «обзоры техники», а «игровые ноутбуки до $800».
Пометка: **беру с оговоркой.** У Ovre ниша задана продуктом, но правило
работает на уровне аккаунтов: «костюм на переговоры», «вечерний образ на
свадьбу гостьей» - разные полосы, а не один аккаунт про всё.

### Двухпроходный сценарий и «тест подстановки»
Источник: https://www.subsub.io/blog/inauthentic-content-why-so-many-creators-are-getting-demonetized
Суть: свой черновик → AI-правка (а не наоборот); проверка «отличит ли зритель
тебя от пяти конкурентов»; разная структура видео; собирать доказательства
производства для апелляции.
Пометка: **беру** «тест подстановки» как пункт LLM-судьи: сценарий должен
нести голос Ovre из `values.md`, а не общий премиум-шум. Двухпроходность беру
наоборот: мой черновик заменяют мои `.business/`-файлы как источник смыслов.

### «ИИ-сценарии запрещены - низкое удержание» (арабский практик Ollex)
Источник: https://lilys.ai/ar/notes/youtube-shorts-automation-20251230/make-money-youtube-shorts-automation
Суть: сценарий пишется руками, темы ищутся в TikTok в режиме инкогнито (чтобы
алгоритм не подстраивался), один голос как бренд канала, загрузка только с
телефона, прогрев аккаунта против «тюрьмы нулевых просмотров».
Пометка: **не подходит** запрет на ИИ-сценарии - это противоречит идее, но
это честное предупреждение: сценарий без вычистки и хуманизации не пройдёт мой
бенчмарк 90%. **Беру** «инкогнито-просмотр» как приём разведки трендов.

### Первый комментарий и сохранения вместо лайков
Источник: https://www.blackhatworld.com/seo/how-are-you-growing-instagram-accounts-organically-in-2026.1802204/
Суть: закрепить вопрос первым комментарием в первые 5 минут; алгоритм весит
пересылку в DM намного выше лайка; 3–5 хэштегов из диапазона 10k–200k; трекшн
3–6 недель, рост 3–6 месяцев.
Пометка: **беру.** Первый комментарий - отдельный шаг автопостинга;
сохранения и пересылки - в набор метрик, по которым агент судит ролик.

## 3. Контроль качества без человека

Сводка приёмов, найденных в коде (источники в разделе 1):
- Технический гейт после рендера: ffprobe на длительность, кодек (yuv420p,
  faststart), чёрные кадры, тишина / клиппинг, наличие субтитров.
- Гейт таймингов: субтитры и визуал привязаны только к реальным Whisper-
  таймстампам; sync-offset субтитров −0.3 с.
- CLIP-гейт кейфреймов до дорогой генерации видео; prompt anchoring героя.
- AV-sync auto-rescue в 4 ступени.
- LLM-судья сценария с порогом и петлёй перезаписи; рубрика из 5 измерений.
- Slideshow risk score - блокировка «слайд-шоу с одинаковой структурой».
- Fallback-ассеты, чтобы конвейер не падал; failover провайдеров (8-модельная
  цепочка, circuit breaker).
- Дедупликация: pHash ассетов, LLM-дедуп тем, память заголовков.
- Checkpoint / resume и бюджетные гейты (observe / warn / cap).
- Модерация: список запрещённых тем, семантический фильтр до рендера.

Пометка: **беру целиком** как чек-лист для этапа «производство». Для меня это
не роскошь, а условие: бенчмарк «90% видео принял без правок» невозможен, если
брак ловлю я, а не конвейер. Из чужого: медицинские заявления заменить на
«обещания посадки / ткани без оговорки» и «цены в тексте» (у меня цены живут в
Tilda, не в ролике).

### Ритуал безопасного скачивания Instagram (Instaloader + практики)

Суть: отдельный «архивный» аккаунт с session-файлом, одна инстанция, паузы 5–15

раза в сутки на профиль. Ротация User-Agent не помогает. Для продакшена -
`curl_cffi` вместо `requests` (TLS-фингерпринт), резидентные прокси $50–200/мес.
Рилсы - самый стабильный тип контента для yt-dlp с куками.
Пометка: **беру.** Это ответ на «каждый день ходить к конкуренту и всё
скачивать» так, чтобы не падало. Оговорка к моему «тысячи конкурентов»: при
таком ритме это десятки профилей в сутки на один архивный аккаунт, тысячи -

### Apify: Reel Scraper / Reel Analyzer / TikTok Scraper

Пометка: **беру** формат отчёта и правило «паттерн только при ≥2 примерах».

Пометка: **беру** как логику ежедневного трекера. Специфика YouTube не мешает.

### Outlier: > 3× медианы последних 30 публикаций
Источник: https://outlierkit.com/resources/outlier-scores/, https://www.octupie.com/blog/instagram-outlier-patterns-by-niche
Суть: 2× - заметить, 3–10× - разбирать, 20×+ - искать внешний фактор.
Разбирать только выбросы у аккаунтов своего размера, искать общее у ≥3
выбросов. Для Instagram: архетипы хуков зависят от ниши (lifestyle - «результат
вперёд», education - вопрос / reveal); saves:likes у выбросов ~1:6, хуже 1:10 -
«нравится, но не ценно».
Пометка: **беру.** Это математика для «понимать закономерности успешных и
неуспешных единиц»: сначала фильтр выбросов, потом умная модель на причинах.
Экономит дорогие токены: анализируем не все ролики, а хвосты распределения.

Суть: история смен title / thumbnail у конкурента - это его A/B-тест,

Пометка: **беру с оговоркой.** В Instagram аналог - смена обложки рилса и

### Swipe file по схеме креативного стратега
Источник: https://adlibrary.com/posts/building-a-competitor-swipe-file-as-a-creative-strategist, https://www.storyflow.so/blog/best-swipe-file-tools-2026
Суть: четыре коллекции (Pattern Library / Competitor Pulse из 3–5 прямых /
Vertical Imports из соседних ниш / Long-runners 90+ дней в открутке). Поля:
hook archetype (problem-agitate, social-proof, curiosity-gap, contrast,
transformation, direct-offer), format, vertical, longevity. При сохранении -
механизм одной фразой («открывает нерешённым напряжением, чтобы досмотрели»).
«Лестница свайпа»: артефакт (бесполезно) → структура → механизм.
Пометка: **беру** схему полей и поле «механизм одной фразой» как обязательное
в карточке ролика в досье. «Vertical Imports» - хорошая идея, до которой сам бы
не дошёл: смотреть не только одежду, а соседние премиум-ниши (украшения,
косметика, интерьер).

### Досье как «LLM Wiki» (Karpathy / Hermes)
Источник: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f, https://hermes-agent.nousresearch.com/docs/user-guide/skills/bundled/research/research-llm-wiki
Суть: три слоя - `raw/` (неизменяемые источники: видео, транскрипты, письма,
скриншоты), `wiki/` (страницы, которые пишет и правит LLM), схема
(`SCHEMA.md` с конвенциями и таксономией). Три навигационных файла: `index.md`,
`log.md` (append-only), схема. Три операции: Ingest (обновить 10–15 связанных
страниц, отметить противоречия), Query (ответ с цитатами становится страницей),
Lint (сироты, битые ссылки, устаревшее, страницы >200 строк делить). Правила
Hermes: страница только для сущности из ≥2 источников, каждая страница ссылается
минимум на 2 других, фронтматтер с `confidence` и `contradictions`.
Пометка: **беру целиком** как структуру папки конкурента:
`raw/{handle}/reels/*.json|*.vtt`, `wiki/competitors/{handle}.md`,
`wiki/patterns/hook-*.md`, `wiki/funnels/{handle}.md`, `index.md`, `log.md`.
Это то, чего в superidea нет: там «маркдаун-документация», здесь - дисциплина,
чтобы она не превратилась в свалку через месяц.

### Basic Memory: «наблюдение с категорией» как единица дописывания
Источник: https://github.com/basicmachines-co/basic-memory
Суть: markdown с фронтматтером, наблюдения как атомарные строки
`[hook] открывает с результата`, `[cta] кодовое слово в комментах`, отношения
как wikilinks с глаголом `posts_like [[Competitor B]]`. Сверху SQLite и
семантический поиск, MCP-инструменты `write_note / search_notes`.
Пометка: **беру** формат наблюдений: ежедневное дописывание досье без
переписывания страницы. И это уже MCP - совпадает с моей архитектурой.

### open-second-brain: «ночной проход» повышает паттерн до правила
Источник: https://github.com/itechmeat/open-second-brain
Суть: ночной детерминированный проход (счётчики + переносы файлов) превращает
повторяющиеся сигналы в подтверждённые правила и «увольняет» неиспользуемые.
Пометка: **беру** как механику: «этот тип хука заходит у конкурента стабильно»
становится правилом только после N подтверждений, и дешёвым кодом, а не LLM.

### youtube-video-insights: агрегаты детерминированно, LLM только для синтеза
Источник: https://github.com/FlorianBruniaux/youtube-video-insights
Суть: субтитры → LLM даёт JSON на видео → SQLite FTS5 → агрегат по каналу
через Counter без LLM + один LLM-вызов на нарратив.
Пометка: **беру** принцип. Это ровно «ум дорогой, конвейер дешёвый»: считать
доли паттернов кодом, умную модель звать один раз на «почему».

Суть: транскрипты с WebVTT-таймстампами → LLM с промптом «кластеризуй

### Reel Analyzer skill (Ootto)
Источник: https://github.com/Ootto-AI/claude-content-skills/blob/main/skills/reel-analyzer/SKILL.md
Суть: разбор в 6 секций: Hook (точный on-screen текст + сказанная фраза в

→ Reel Scripter → Reel Builder.
Пометка: **беру** как шаблон карточки ролика и как цепочку «разбор → хук →
сценарий». Разделение «техника vs контент» - защита от подавления за копипаст и
от нарушения тона бренда.

### Таксономия признаков для разметки
Источники: https://arxiv.org/html/2602.22299v1 (17 стратегий первых 3 секунд + 8 акустических признаков), https://www.highviz.io/instagram-reels-report/ (тип первого кадра, текст-оверлей, длина), https://inflowave.io/tools/viral-video-analyzer (6 точек оттока: 0–2, 3–5, 8–12, 15–22, 28–35 с и точка петли), https://www.gettranscribe.ai/ (поля «на ролик» и «на аккаунт»)
Суть: фиксированная таксономия, чтобы LLM размечал одинаково: тип хука, тип
первого кадра (лицо / b-roll / текст / беззвучный), длина, наличие речи, CTA-
механика (кодовое слово / follow / ссылка), точки оттока. Из Highviz: 0–15 с
дают 66% досмотра, открытие «b-roll / cinematic» и «лицо в камеру» дают ~9%
вовлечения против 3.3% у беззвучных; текст-оверлей повышает вовлечение, но
снижает досмотр.
Пометка: **беру** таксономию как `SCHEMA.md` досье. Акустические признаки
(темп, питч) - беру, это признак, о котором сам бы не подумал: голос аватара
можно подбирать по данным. Рекламная специфика arXiv не мешает.

### Три слоя текста на ролик
Источник: разделы выше, https://github.com/m-bain/whisperX
Суть: транскрипт с пословными таймстампами (WhisperX), подпись, on-screen текст -
хранить все три; для роликов без речи нужен OCR / видеомодель.
Пометка: **беру.** Для fashion-контента on-screen текст часто и есть хук, а речи
может не быть вовсе - без OCR половина конкурентов останется «пустой».

Пометка: **беру.** Longevity рекламы как прокси-эффективность без доступа к

## 7. Автопостинг на много аккаунтов

### Instagram Graph API: лимиты и «белые» практики
Источник: https://developers.facebook.com/docs/instagram-platform/content-publishing/, https://bundle.social/blog/instagram-api-rate-limits, https://mixpost.app/blog/automate-instagram-posts-safely
Суть: 100 API-публикаций за скользящие 24 ч на профессиональный аккаунт;
реальную квоту показывает `GET /<IG_ID>/content_publishing_limit`; ошибка
2207042 - не ретраить. Медиа на публичном URL, JPEG. Meta разрешает автопостинг
через Graph API, запрещает масс-лайки / фолловы / скрейпинг. Практики: ≤25
постов в сутки на аккаунт, 3–4 ч между постами, +20% частоты в неделю,
разброс времени ≥15 мин, 80% оригинального контента, 30+ наборов хэштегов,
ответы на комментарии вручную.
Пометка: **беру** как правила постера. Это подтверждает мой опыт «официальный
API не роняет охваты» и даёт цифры, где предел.

### Инструменты: считать по постам, не по профилям
Источник: https://github.com/gitroomhq/postiz-app, https://postiz.com/mcp, https://mixpost.app/, https://docs.upload-post.com/, https://www.blotato.com/, https://zernio.com/, https://www.blotato.com/blog/best-social-media-api-tools
Суть: Postiz (OSS, MCP одной ссылкой, cloud $29–99), Mixpost ($299 разово,
встроенный MCP, изолированные workspace), Upload-Post (hosted MCP на 50
инструментов, аудиты TikTok / YouTube пройдены провайдером), Blotato ($29
flat, генерация + постинг), Zernio ($1–6 за аккаунт, 280+ MCP-инструментов,
DM и аналитика), Post for Me ($10 за 1000 постов, безлимит аккаунтов).
Пометка: **беру с оговоркой.** Для 10–50 аккаунтов считать цену за пост.
Self-host (Postiz / Mixpost) означает свои OAuth-приложения Meta и аудиты -
пока трафик только в Instagram, это одно приложение, посильно. Для «MCP как
продукт» позже: рынок уже устроен как hosted URL + ключ, свой Instagram MCP

### Как разводить контент по аккаунтам, чтобы не считалось дублем
Источник: https://renderio.dev/blogs/tiktok-duplicate-content-detection/, https://www.blackhatworld.com/seo/can-i-post-same-reels-on-multiple-accs.1704401/, https://petapixel.com/2026/04/30/new-instagram-policies-target-reposted-content/
Суть: у платформ 4 слоя детекции (хэш файла, перцептивный хэш кадров, аудио-
fingerprint, поведение: время загрузки, устройство, похожесть описаний).
Наказание - подавление охвата второй копии и всего аккаунта. Instagram с
30.04.2026: если «большая часть» месячных постов - неизменённый контент,
аккаунт не рекомендуется; кропы и водяные знаки не спасают. Консенсус: менять
хук первых 1–2 с, визуал, оверлеи, длину, подпись; каждому аккаунту свой график,
не постить одновременно. Вариации на уровне производства (другой хук, голос,
обложка, порядок сцен), а не пост-обработкой.
Пометка: **беру.** У каждого аккаунта своя «полоса» (повод, персона, угол), и
вариативность закладывается в JSON сцен, а не в перекодирование. Это меняет мою
формулировку «как из пулемёта на много аккаунтов»: пулемёт стреляет разными
патронами.

## 8. Оркестрация агентом и передача контроля

### Стратегия в файле, который агент сам правит по метрикам (OpenClaw)
Источник: https://buildtolaunch.substack.com/p/openclaw-autonomous-agent-live-demo, https://lumadock.com/tutorials/automate-social-media-openclaw-scheduler
Суть: SOUL.md (голос бренда и запреты) → утренний ресёрч 5 тем → батч
черновиков в Telegram → одобрение → публикация с логом ID → обход комментариев
→ недельный отчёт с топ / анти-топ и идеями на следующую неделю. Агент за 2
недели по метрикам сам переписал свой strategy-файл. Ловушки: агент «забывает»
инструкции, кроны тихо пустеют - нужны персистентная память и проверка «крон
отработал → пост появился».
Пометка: **беру.** `strategy.md`, который агент правит по цифрам, - простейшая
реализация «переосмысливать стратегию и рефлексировать». Telegram как UI
валидации - совпадает с моим «задача в Telegram». Проверка «крон отработал» -
обязательна, я это уже видел на расписании.

### Метрики «против себя» и выученные правила как ограничения (youtube-automation-agent)
Источник: https://github.com/darkzOGx/youtube-automation-agent, https://dev.to/wcamon/i-let-ai-agents-run-my-youtube-channel-for-6-weeks-heres-what-actually-happened-21b1
Суть: CTR / retention / watch-time сравниваются с собственной историей канала,
а не с чужими цифрами; A/B-арм побеждает при 95% evidence без просадки
удержания; одобренный вывод становится constraint следующего планирования.
Из 6-недельного эксперимента: мерить like-rate и watch-time, не просмотры; лаг
аналитики 48–72 ч - цикл недельный, не дневной; агент обязан помнить все
решения.
Пометка: **беру.** «Выученное правило → ограничение в следующий промпт» - это
и есть механика, по которой процент принятого мной растёт к 90. Оговорка к
моему «ежедневная рефлексия»: цифры приходят с лагом, ежедневно можно снимать,
решать - еженедельно.

### Роутинг моделей по шагам (Opus / Sonnet / Haiku) и по шотам (видео)
Источник: https://www.mindstudio.ai/blog/claude-code-advisor-strategy-opus-sonnet-haiku, https://jsmanifest.com/claude-model-routing-subagents, https://www.atlascloud.ai/blog/guides/cheapest-ai-video-generation-api-2026
Суть: дорогая модель - стратегия, разбор метрик, отбор идей, финальный QA;
средняя - сценарии и подписи; дешёвая - теги, классификация комментариев,
ремиксы подписей под аккаунты; экономия 30–50%. Видео: массовые клипы на
Seedance Fast / Veo 3.1 ($0.03–0.09 за секунду), hero-кадры на Kling 3.0;
считать эффективную цену с учётом 2–3 генераций на годный клип (~$0.5–1 за
клип, $5–50 за собранный ролик).
Пометка: **беру.** Совпадает с моим «ум дорогой, конвейер дешёвый» и даёт
цифры. Шот-левел роутинг видео - приём, о котором сам не думал.

### Claude Code cron + HeyGen MCP
Источник: https://www.mindstudio.ai/blog/ai-video-production-workflow-claude-code-heygen-mcp
Суть: агент пишет JSON-сценарий сегментами <350 символов, зовёт `create_video`
/ `get_video_status`, опрашивает рендер 2–10 мин, склеивает FFmpeg. 90-секундный

вызовами, MCP рвётся на длинных задачах.
Пометка: **беру** как эталон связки «агент → аватар по MCP». Аватар HeyGen
говорит, но в мою одежду не переодевается - одежда идёт вставками (раздел 9).

Источник: https://github.com/khaoss85/youtube-autopilot, OpenClaw выше
Суть: одобрение идеи / сценария и одобрение финального ролика; `publish` -
отдельная команда с «do not publish» в промпте черновиков.
Пометка: **беру с оговоркой.** У меня три гейта (выбор сценария, видео,
постинг), и они снимаются по очереди на 90%. Совпадает по духу: гейт - это
точка измерения, а не вечная кнопка.

### Разделять ресёрч и постинг по ключам
Источник: OpenClaw / LumaDock выше
Суть: агент с доступом в веб не имеет ключей постинга и наоборот - меньше
blast radius, если агент прочитает инструкцию в чужом контенте.
Пометка: **беру.** Агент, который ходит по чужим воронкам и читает чужие
письма, - идеальная мишень для инъекции; постить он не должен уметь.

## 9. Аватар и AI-модели для одежды

### VTON вместо «нарисовать одежду»: роутинг по категории и лицензии

### Консистентная «своя модель»: LoRA + turnaround + референсы
Источник: https://workingnotworking.com/flux-2-lora-training-guide/, https://apatero.com/blog/ai-character-turnaround-sheet-generation-guide-2026, https://www.blackhatworld.com/seo/ai-ofm-in-2026.1825851/
Суть: LoRA на лицо (20–40 фото, разные углы и свет) + лист фронт / профиль /
спина + референс-изображения (Wan 2.7 до 20, Kling start / end frame). Из
практики BHW: «новое лицо в каждом посте читается как фейк и быстро

Пометка: **беру.** Одна модель на коллекцию, одна на аккаунт-«полосу».
Совпадает с моим опытом, что покупательницы принимают аватар.

### Референс-пакет на вещь, правило одного изменения, motion-бриф
Источник: https://parkmagazineny.com/nano-banana-to-seedance-2-5-how-to-turn-fashion-photos-into-video-ads-without-changing-the-clothes/, https://www.wearview.co/blog/best-ai-image-to-video-tools-for-fashion
Суть: на каждую вещь - фронт, бок / спина, деталь ткани крупно, письменная
спецификация (длина, вырез, фактура). При подготовке ключевого кадра менять
только одно (фон или свет), не трогая позу и аксессуары. В motion-брифе один
тип движения («quarter-turn», «locked medium-full shot», «slow push-in»),
избегать сильного движения на принтах; многослойные комплекты - отдельные
клипы на вещь. Seedance 2.0 лучший по физике ткани, Kling 3.0 Pro второй (шёлк
«с весом», 4K держит вязку), Veo 3.1 - 8-секундный лимит и дрейф на продлениях.
Пометка: **беру целиком.** Это производственный регламент для костюмной
группы, где посадка и ткань - весь продукт. Референс-пакет ложится в ту же
`raw/`-структуру, что и досье конкурентов, только про нас.

### Доверие покупательниц: ломает не AI, а видимые ошибки
Источник: https://stylitics.com/resources/blog/ai-fashion-photography/, https://www.wearview.co/blog/brands-using-ai-fashion-models, https://news.designrush.com/no-ai-disclaimers-brands-consumer-trust-2026

Пометка: **беру с оговоркой.** Раскрывать спокойно («модель сгенерирована,

ясным возвратом. Оговорка серьёзная: 35% негатива среди женщин при премиум-
цене - это риск, который надо мерить продажами, а не вовлечением. В why-now я
написал, что покупательницы принимают аватар; эти цифры говорят «принимают,
пока не увидят ошибку в ткани».

## 10. Арабский рынок: что там есть своего

### Диалектные TTS и слой предобработки текста под озвучку
Источник: https://tts.darijat.com/, https://lahajati.ai/, https://github.com/nipponjo/tts_arabic
Суть: платформы выбирают не «голос», а «диалект под страну»; перед TTS текст
проходит отдельный слой: авто-огласовка неоднозначных слов, числа словами,
темп ниже стандартного, короткие предложения, запрет смешивать литературный и
разговорный в одном тексте.
Пометка: **не подходит** напрямую (арабский), но **беру** сам слой по аналогии
для русского: ударения в омографах (зáмок / замóк, «бóльшая»), числа и цены
словами, буква ё, короткие фразы, единый регистр (не смешивать «вы» и «ты»).
В англоязычных пайплайнах этого слоя нет вообще, а русский TTS без него
спотыкается так же, как арабский без огласовок.

### KPI «меньше $2 за ролик» в реальных ТЗ и «нулевой бюджет»
Источник: https://nafezly.com/project/43785 (ТЗ заказчика, ~05.2026), https://www.youtube.com/watch?v=4YId1SzUIvI (MoneyPrinterTurbo в Colab)
Суть: реальные заказы формулируют приёмку как себестоимость за ролик;
рендер в Google Colab бесплатно; edge-tts, Pexels, Gemini free tier.
Пометка: **беру** метрику «$ за ролик» как обязательное поле лога каждого
ролика (в n8n-шаблонах это тоже пишут в таблицу). «Нулевой бюджет» **не
подходит**: качество премиум-ролика стоит денег, экономлю на роутинге, а не на
голосе.

### Форматы без речи
Источник: https://www.facebook.com/ihtirafadsense/posts/ (02.05.2025)
Суть: каналы-миллионники «без единого слова» снимают проблему TTS и языка.
Пометка: **беру с оговоркой.** Для одежды ролик «только движение ткани +
музыка + on-screen текст» - легитимный формат Reels (Highviz: b-roll-открытие
даёт вовлечение выше среднего). Не как основной, как одна из «полос».

### Готовые n8n-воркфлоу как товар
Источник: https://khamsat.com/ai-machine-learning/ai-automation/3912100
Суть: JSON-воркфлоу «сценарий → видео → загрузка» продаётся как товар;
заказы «система под ключ» за $250–500.
Пометка: **не подходит** как источник решения (качество «сток + TTS»), но
подтверждает: «MCP как продукт» позже - рынок готов покупать конвейер, а не
ролики.

### Совпадения с англоязычными практиками
Тот же стек (LLM → ElevenLabs → Pexels или Seedance → Creatomate / Shotstack →
Blotato), те же ниши, те же предупреждения про reused content и робоголос,
та же воронка гуру «челлендж → курс → услуга». Ничего принципиально нового
кроме TTS-слоя и ценовых ориентиров арабский сегмент не дал; حسوب I/O и
Telegram-сообщества по теме не найдены, مستقل / خمسات закрыты для чтения.

## 11. Ручные обходы: как это делают без продукта

- Google Sheets / Airtable как очередь: одна строка = один ролик, колонка
  статуса, воркфлоу берёт строку за запуск и пишет обратно ссылку, стоимость,
  токены. **Беру** как формат журнала даже при агенте: мне нужно видеть очередь.
- Таблица разведки «одна строка = один пост» (handle, дата, URL, формат, тема,
  тип хука, лайки / комменты / сохранения, заметка), 10–15 минут в день, через
  2–4 недели видны паттерны. **Беру** как ручной прогон на одном конкуренте

- Apify по расписанию → Sheets / Notion без кода, хуки тегировать руками.

- Воронка руками: отдельная почта на конкурента, пройти «био → лендинг → форма

- YouTube с 15.07.2025 демонетизирует шаблонные массовые видео с одинаковым

  рекомендаций; 31.08.2026: AI-персона без метки профиля вне Reels / Explore.

## Итог: что беру, до чего сам бы не додумался

1. **Досье как LLM Wiki** с `raw/` / `wiki/` / `index.md` / `log.md` / схемой и
   еженедельным lint - иначе markdown-документация станет свалкой.
2. **Outlier-фильтр 3× медианы + saves:likes** до того, как звать умную модель:
   причины ищем в хвостах распределения, а не во всех роликах.
3. **Паттерн засчитывается при ≥2–3 примерах на ≥2 аккаунтах**, агрегаты
   считает код, LLM зовётся один раз на синтез; ночной проход повышает паттерн
   до правила после N подтверждений.
4. **Хук = окно 0–5 с по таймстампам**, три слоя текста (речь / подпись /
   on-screen через OCR), акустические признаки голоса как отдельный слой.
5. **Slideshow risk score, CLIP-гейт, AV-sync auto-rescue, pHash-дедуп** -
   готовый QC без человека, условие для бенчмарка 90%.
6. **Сцена = HTML-шаблон** (Pixelle / HyperFrames) - брендовая моушн-графика,
   которую агент пишет как HTML.
7. **VTON с роутингом по категории и проверкой лицензии**, LoRA-модель на
   коллекцию, референс-пакет на вещь, четыре чек-пункта Fit / Fabric / Print /
   Logo.
8. **«Бросить корзину и ждать письмо»**, catch-all на поддомене, longevity
   рекламы как прокси-эффективность, ESP по link-wrapper.
9. **Каждому аккаунту своя полоса** и вариативность в JSON сцен, не в
   перекодировании; ресёрч и постинг на разных ключах.
10. **Слой предобработки текста под TTS** (ударения, числа словами, ё) по
    аналогии с арабской огласовкой.
11. **Strategy-файл, который агент правит по метрикам**, решения еженедельно
    из-за лага аналитики 48–72 ч; «крон отработал → пост появился» проверяется.
12. **$ за ролик как поле лога** и шот-левел роутинг видеомоделей.

## Чего не нашли

- Готового open-source «пройти воронку и собрать письма» - только конструктор
  из browser-use / Stagehand + AgentMail / catch-all.
- Проекта, который на большом досье вытаскивает причины, а не пересказ:
  ближайшее - когортный анализ Apify и правило «≥2 примеров» у ScrapeCreators.
  Главное допущение why-now этой разведкой не закрыто, только подкреплено
  методикой.
- Reddit и X недоступны инструментам разведки: r/NewTubers, r/youtubeautomation,
  r/n8n не прочитаны. Если нужна эта дыра - отдельный прогон через браузер.
- Русскоязычных источников не смотрели.
- Кейсов премиум-fashion-бренда с полностью автоматическим Reels-конвейером -
  нет; всё, что нашлось про одежду, - e-commerce с UGC-эстетикой и
  вендорские блоги.
